Get started

Run SANA on your own agent and read its diagnosis.

1. Prerequisites

Commands marked [FILL IN] are placeholders — replace them with the eval repo's exact CLI before publishing.

  • Python 3.10+ and git
  • An OpenAI API key (the paper evaluates gpt-5.4-nano and gpt-5-mini)

2. Get the code

git clone https://github.com/Austin-Senna/exploratory-qa-eval
cd exploratory-qa-eval
pip install -e .

The repo ships the SANA ablation tools (plan_ideal, search_ideal, execute_ideal), the task profiles, and the evaluation harness.

3. Inspect a task profile

Each profile holds the source sequence, sanitized subquestions, and execution records (see Method). These drive the idealized tools.

# [FILL IN — exact path/command from the repo]
ls tasks/        # LakeQA + converted KramaBench profiles

4. Run an ablation condition

Pick one mode per axis. Holding two axes at Ideal and varying the third isolates that component's contribution.

# [FILL IN — exact CLI from the repo]
python -m sana.run \
    --benchmark lakeqa_mini \
    --model gpt-5.4-nano \
    --plan ideal --search bm25 --data-analysis ideal \
    --budget 30 --out runs/search_bm25/

5. Read the diagnosis

Compare semantic match across conditions. If idealizing an axis closes a large gap, that component is your bottleneck. The gap that remains when all three are idealized is attributable to the agent's policy — evidence tracking, source commitment, intermediate validation, and stopping criteria.
